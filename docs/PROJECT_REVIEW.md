# Анализ изменений и Docker

Проверено состояние репозитория на коммите `667da7e` и изменения, добавленные
в рамках регистрации и авторизации. Рабочее дерево перед началом задачи было чистым.

## Изменения после предыдущей реализации

В коммите `478f13a` объединены frontend и база данных. В `667da7e` добавлены
offline-evaluator, 30 синтетических кейсов и вычисление precision/recall@k,
достоверности цитат, статусов, ложных отказов и задержек. Поиск обрабатывает
неположительный limit и увеличивает пул кандидатов при большом k.
Проверка цитат отвергает цитату из одних пробелов. Транспорт LLM логирует
тип ошибки и HTTP-статус, исключая тела ответов и ключи. Эти изменения сохранены,
их существующие тесты проходят вместе с новыми проверками авторизации.

Конкретный пробел безопасности исходной версии состоял в общем доступе к
списку чатов и истории по UUID. Новый `owner_id`, обязательная серверная сессия
и фильтры владельца устраняют этот доступ. Новый профиль возвращает только
имя, email и ID. Сервер хранит хеши паролей и сессионных идентификаторов.

## Docker

Приложенный скриншот фиксирует сбой получения метаданных базовых образов
Python, Node и nginx из Docker Hub. Подробности исходной сетевой ошибки
на скриншоте отсутствуют, поэтому конкретную причину DNS/TLS установить по нему
нельзя. Во время проверки Docker Desktop был доступен. Все три образа успешно
загружены через `docker pull`, этап получения метаданных затем завершился.

При полной сборке воспроизведён дополнительный `EIDLETIMEOUT` при загрузке npm.
Диагностика отдельным контейнером показала тайм-ауты публичных tarball-файлов
`scheduler`, `pretty-format` и `picomatch`. В Dockerfile добавлен постоянный
BuildKit-кеш npm, ограниченные повторные загрузки и тайм-аут 60 секунд.
Сетевой аудит npm исключён из сборочного шага. Повторная установка зависимостей
прошла за 13 секунд. API и web-образы успешно собраны и запущены.

nginx передаёт исходный Host вместе с портом, чтобы браузерный Origin корректно
проверялся API. SQLite находится в постоянном volume, доступном процессу API.
Пользовательский `.env` с ключами остаётся вне Docker-образов и Git.

## Проверенный результат

- Backend прошёл 85 тестов, включая evaluator и проверки безопасности аккаунтов
- Frontend прошёл 16 компонентных тестов и 12 сценариев Playwright
- Проверены мобильные формы и WCAG-проверки axe
- Production-сборка TypeScript/Vite завершилась успешно в Docker
- Через настоящий nginx проверены регистрация, сессия, CSRF, изоляция пользователей,
  смена пароля, выход и сохранение сессии с чатом после перезапуска API
- Production-интерфейс отдельно проверен в Chromium через порт 8080 с действующей CSP

MVP работает локально на `http://127.0.0.1:8080`. Генерация ответов зависит от
выбранного провайдера LLM. Браузерные тесты используют отдельный тестовый gateway
и временную БД. Тест безопасности реального Docker-стека не обращается к LLM.

Особенности миграции старых чатов и границы локальной регистрации описаны в
[AUTH.md](AUTH.md).

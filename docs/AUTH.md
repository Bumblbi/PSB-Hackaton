# Пользователи и сессии локального MVP

Пользователи хранятся в той же SQLite, что и чаты. В Docker это файл
`/app/data/db/legal.db` в постоянном volume `psb-ackaton_sqlite_data`.
При запуске Python из `backend/` используется путь из `DATABASE_URL`.
Таблицы создаёт Alembic-миграция `0003` при старте API.

## Учётные записи

Регистрация открыта для пользователей локального приложения. Email служит
логином и нормализуется без учёта регистра. Пароль содержит 15–128 символов,
поддерживает Unicode и пробелы. В БД хранится Argon2id-хеш с индивидуальной
солью, параметрами 19 MiB / 2 прохода / 1 поток. Ориентиром служат рекомендации
OWASP по аутентификации и хранению паролей.
[Authentication Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Authentication_Cheat_Sheet.html),
[Password Storage Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html).

Подтверждение email, почтовое восстановление доступа и MFA остаются за рамками
этого локального MVP. Рабочий аккаунт создаётся через форму регистрации.
Предустановленного администратора или общего пароля нет.

## Сессии и защита запросов

Сервер выдаёт случайный идентификатор из 32 байтов. Его SHA-256 хранится в
`auth_sessions`. Cookie имеет HttpOnly, SameSite=Lax, Path=/ и ограниченный
срок жизни. Клиент хранит CSRF-токен в памяти приложения и восстанавливает
его через `/api/v1/auth/session`.

POST-запросы проверяют Origin, Sec-Fetch-Site и заголовок
`X-Requested-With: legal-workspace`. Для защищённых операций требуется
сессия и `X-CSRF-Token`. Вход и регистрация проверяют происхождение
и обязательный пользовательский заголовок до создания сессии.
[Session Management Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html).

Сессия действует до 8 часов и завершается после 30 минут без обращения к
защищённым API. Настройки `AUTH_SESSION_HOURS` и `AUTH_IDLE_MINUTES` позволяют
изменить эти интервалы. Выход отзывает текущую серверную сессию. Смена пароля
отзывает все сессии пользователя. При повторном входе текущая cookie заменяется.

Ограничения попыток сохраняются в `auth_throttle` и переживают перезапуск API.
Для входа предусмотрены 30 попыток с IP и 10 на email за 5 минут. Для регистрации
предусмотрены 20 попыток с IP и 10 на email в час. Через nginx несколько локальных
клиентов могут разделять лимит адреса прокси. Приложение запускается с одним API worker.

Для локального HTTP используется `AUTH_COOKIE_SECURE=false`. При публикации
через HTTPS требуется `AUTH_COOKIE_SECURE=true`, что также включает имя cookie
`__Host-legal_session`. Доверенные дополнительные Origin задаются точным списком
`AUTH_TRUSTED_ORIGINS`. Vite и nginx сохраняют исходный Host с портом.

## Доступ к данным

Все пользовательские API требуют входа. Новый чат принадлежит создавшему его
пользователю. Списки, счётчики, чтение истории и отправка сообщений проверяют
владельца на сервере. Чужой чат возвращает 404. Документы общего корпуса доступны
всем зарегистрированным пользователям. Dev-операции импорта дополнительно
требуют настроенного `ADMIN_TOKEN`.

Старые чаты, созданные до авторизации, сохраняются с `owner_id = NULL` и скрыты
из пользовательских списков. Миграция сохраняет их сообщения и цитаты.
Назначать владельцев старых данных следует оператору после определения их
происхождения. Первый зарегистрировавшийся пользователь не получает их автоматически.

## API

| Метод | Путь | Назначение |
| --- | --- | --- |
| POST | `/api/v1/auth/register` | Имя, email, пароль, создание сессии |
| POST | `/api/v1/auth/login` | Вход, новая cookie и CSRF-токен |
| GET | `/api/v1/auth/session` | Текущий профиль и CSRF-токен |
| POST | `/api/v1/auth/logout` | Отзыв сессии |
| POST | `/api/v1/auth/password` | Текущий и новый пароль, отзыв всех сессий |

Запросы возвращают только публичный профиль. Ошибки входа одинаковы для
неизвестного email и неверного пароля. Ответы API имеют Cache-Control=no-store.
Обработчик валидации исключает содержимое запроса из ошибок.

## Проверки

Backend-тесты проверяют политику паролей, хеши, атрибуты cookie, CSRF, Origin,
владельцев, выход, блокировку пользователя, тайм-ауты, лимиты попыток и смену пароля.
Playwright проходит регистрацию и вход через браузер, проверяет изоляцию между
двумя браузерными сессиями и доступность форм. `backend/tests/compose_smoke.py`
проверяет настоящий nginx/API и перезапускает контейнер API для проверки сохранности.
